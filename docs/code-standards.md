# 开发与代码规范

## 本地检查

在 `frontend/` 目录执行：

```bash
npm ci
npm run check
npm run lint:clients
npm run build:pages
npm run build:connected
```

`check` 依次检查 ESLint、Prettier 和领域测试；`lint:clients` 检查 `mobile-client/src` 和 `uni-app/src`。提交前使用 `npm run format` 统一管理端格式。CI 使用同样的检查命令。

## 前端职责

- 页面组件负责展示、交互和请求状态，领域规则放入 `src/domain/`，接口封装放入 `src/connected/platformClient.js`。
- 联网与静态演示共用费率时间轴、计费预览和报修等待时间规则。联网费率支持多个时段，静态演示按站点全天单价展示。
- 费率保存前校验有效时间和重叠；未覆盖全天时显示缺口并停止试算。配置过程允许暂存部分时段，后端仍负责最终校验。
- 异步读取区分加载、失败与空数据；关闭弹窗、切换记录和退出登录后忽略旧请求。提交期间禁用重复操作。
- 报修候选人员由后端按报修归属返回，页面不能用“当前筛选的运营商”代替记录归属。历史负责人保留显示，停用或越权账号不能重新分派。

## 刷新规则

管理端沿用每5秒刷新设备、插座、订单和报修。站点、平台用户和运营商基础信息每60秒刷新；手动刷新立即读取基础信息。基础信息读取失败不推进缓存时间。页面隐藏、编辑、提交和会话切换沿用现有保护逻辑。

## 后端职责

实际多运营商业务后端位于配套项目 `ev-charging-platform/backend/`。运营商与团队控制器接收参数、验证请求并返回结果；业务判断与事务分别放入 `OperatorService`、`TeamService`。最后一名管理员保护、归属检查和数据库锁保留在服务层。

`backend/charging-service/` 保留独立的原单平台实现。它没有运营商实体，不能直接覆盖为配套项目的多运营商服务；两个实现共同维护健康检查响应和报修人员查询接口，多运营商权限测试在配套项目执行。

统一使用 `common.dto.ApiResponse`。成功响应沿用业务接口的200或201状态码；健康检查同样返回200和 `data.status=UP`。接口返回专用人员视图，不序列化用户密码。

新增接口或调整权限时，覆盖正常请求、无权限、其他运营商、停用账号和返回字段。修改事务时检查回滚和并发条件，避免仅依赖前端隐藏按钮。

## 命名与格式

- Java 类使用大驼峰，方法与变量使用小驼峰；Vue 组件沿用现有文件名。
- JavaScript 使用单引号、分号、两空格缩进和LF换行，由配置统一处理。
- 删除无用导入和失效变量；确需保留的未使用参数以下划线开头。
- 金额计算和日期处理集中在领域模块，展示层不重复实现业务规则。
- 测试使用独立数据和端口，不清空正在演示的数据库，不把生成文件、依赖或本机配置提交到仓库。
