# 毕设系统完善与验收设计方案

日期：2026年11月14日。状态：供审阅，尚未开始功能实施。

## 目标与范围

保留现有平铺菜单和整体视觉风格，优先统一最终联机系统、收费口径与文档，再完善管理端操作联动、客户端使用体验和验收证据。以校园为重点，其他场景只验证共用流程。已有功能优先复用，只补实际缺口。

不增加多级折叠菜单；本轮也不合并“故障报修”和“运营与告警”的入口。暂不增加预约、钱包、优惠券、AI预测、商业营销、硬件安全保护或正式资金通道。页面优化不承诺这些能力。

## 最终演示基线

现有源码至少包含两条实现路线，不能汇总两套代码的能力后称为同一系统已完成。

- 按此前已核实的联机组合，先以 `frontend/src/connected/ConnectedApp.vue` 管理端、工作区的“云创用户端”和 `ev-charging-platform/backend` 为运行基线候选；实施前通过实际启动命令、接口及数据库再次确认。
- `campus-ebike-charging/uni-app` 与 `backend/charging-service` 中较完整的能力作为对照；没有在选定联机系统验证的功能，一律列作待补，不因另一目录存在代码就算完成。
- 若此前基线已经更新，按最新可运行证据修订基线清单，并记录选择理由。不得在未验证接口兼容性时切换客户端或覆盖数据库。
- 管理端、用户端共用同一业务后端和数据库；Pages 是独立静态演示。收藏、最近浏览和消息已读等本机偏好不纳入跨设备同步承诺。

## 已确认口径

新订单只计算电费；预计金额统一称“预计电费”，按订单电价快照分段累计并在最终结算时保留两位小数。历史账单按原记录保留，不篡改历史金额。旧数据若包含服务费，只在必要的历史详情中标明历史记录，不进入新订单配置和新订单说明。

充满自停保留已有方案，明确依据功率变化和持续低功率条件推断结束，不显示虚构电池百分比。软件曲线与设备上报分开说明，只验收最终联机系统实际支持的路径；未支持的设备路径列为后续扩展。阈值、持续时长和最长时限取选定实现，不重新发明算法。

支付先区分充电状态和支付状态。本地模拟支付及已配置的支付宝沙箱测试分别说明，正式收款不作为验收要求；是否已通过沙箱交易验证以实际记录为准。

## 管理端调整

1. 保留当前平铺菜单；“数据统计”建议改名“运营概览”，“收费规则”建议改名“电价规则”。其他入口保持现有名称，避免无收益的改动。
2. 首页突出今日订单、结算电量、结算电费、当前空闲插座、待处理报修和异常设备。站点、设备总数作为资源概况，不随历史日期变化。账单金额不写成实收收入。
3. 首页重点保留订单/电费趋势、启动时段、站点对比和待办。优先复用现有图表，用户增长等次要图表减少首页占比，不增加独立大屏。
4. 所有日期统计标明依据开始时间或结束时间；同一组件及明细采用同一归属规则。当前状态指标明确标“当前”，不受历史日期筛选误导。
5. 待处理报修与异常设备卡片可进入相应筛选结果；有具体报修记录时打开该记录，无记录编号时进入带站点/状态条件的列表。
6. 站点使用现有详情形式增加设备排布、关联订单、报修、电价查看入口。允许详情页签，不改变侧边菜单层级；关联只使用真实 ID。
7. 订单详情统一显示方案、计量来源、用电量、电费、支付状态和结束原因。充满自停不得被误标为普通定时；历史缺失值显示“未记录”。
8. 报修、告警各保留现有业务和权限。告警确认只记录核对，报修结案与故障恢复不能自动相互代替。

## 用户端调整

1. 首页优先显示当前启动中/充电中任务，点击直达本人订单；待支付与充电中区分，不把待支付当作插座仍被占用。
2. 站点卡片突出名称、地址、可用状态、空闲/总插座和可获得的电价信息。无有效电价显示“查看电价”或“暂未配置”，不虚构“起价”、距离和营业时间。
3. 场景筛选、收藏、最近浏览优先复用已有实现；若选定客户端缺失，再按收益补入。菜单过密时采用横向筛选或简洁筛选面板，不把设备排细节堆在首页。
4. 站点详情负责设备排布和A/B插座选择；充电确认页显示方案、预计电费及结算说明，未知数据不补零。
5. 充电详情显示功率、时长、电量、电费及结束原因；充满自停说明必须匹配实际实现，软件模拟与真实测量不混写。
6. 从插座/设备发起报修自动带入资源ID；用户能查看本人处理进度。已有工单时间线直接复用。
7. 统一加载、无结果、站点无设备、全部不可用、网络失败和登录过期提示。失败后保留必要上下文，防重复提交，不用演示数据替代接口成功。

## 文档与交付

修正最新任务书残留的服务费句子；两份文档统一电费、方案、计量、支付及客户端/管理端一致性口径。任务书描述功能与验收要求，不写具体菜单位置。开题报告强调资源占用、订单结算与运维处理的一致性，不夸大创新或实地部署。

补一份“需求—接口/页面—测试证据”对照表，完成情况分为已有代码、联调通过、待验证，不能混写。整理架构图、ER图、充电/支付/插座状态图、报修处理流程图、部署说明及答辩演示脚本。学校模板、身份资料、签字区和进度安排保持原有内容，除非发现明确矛盾。

## 验收标准

- 用户端启动后，管理端显示同一订单、同一插座占用；结束后金额、原因和插座释放一致。
- 只对新订单计算电费；跨时段/跨日和费率调整后旧订单仍按快照结算。
- 同插座并发启动、重复结束/支付、越权访问和重复报修提交均按已有规则处理。
- 定时结束、提前结束和充满自停分别验证；短时低功率不误判，断线及重启不伪造连续采样证据。只测试实现支持的路径。
- 报修提交、分派、处理、反馈可追踪；告警确认不会直接解除故障。
- 历史缺失信息、零设备站点、空列表、登录失效、刷新失败与移动端窄屏均可正常使用。
- Pages 静态演示和联机系统分别验收，不以静态页面截图证明联机功能通过。

## 实施顺序与完成边界

先完成基线确认和文档遗留修正，再做核心页面联动；随后优化视觉细节，最后做联机验收和文档排版。每阶段交付可检查结果；遇到功能缺失先实现最小业务闭环，不扩展为新模块。代码提交、推送与Pages发布作为独立交付动作记录，本方案本身不代表已发布。
