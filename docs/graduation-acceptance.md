# 毕设最终联机验收记录

记录日期：2026-11-14。应用场景覆盖校园、住宅小区、医院、产业园区、办公区及商业配套；校园为重点展示场景，其他分类验证通用业务，不代表实际建站。

## 唯一验收组合

| 层次 | 目录及入口 | 说明 |
| --- | --- | --- |
| 管理端 | `campus-ebike-charging/frontend`，`npm run dev:connected` | 平铺导航，默认5201，通过`/api`访问业务后端 |
| 用户端 | 本仓库`mobile-client`，`npm run dev:connected` | 当前本地配置5198，H5/微信小程序由同一份uni-app源码构建 |
| 后端 | 同级`ev-charging-platform/backend`，Java 17 | 业务接口默认8081，部署数据库为MySQL |
| 隔离验收 | 后端`GraduationPreviewServer`与`bike-schema.sql` | 仅绑定127.0.0.1，独立H2内存数据，3站/2设备/4插座；不是现有业务库 |
| 独立演示 | `frontend`的Pages模式 | 浏览器模拟数据，不作为两端一致性证据 |

本仓库内`uni-app`与`backend/charging-service`保留为参考实现，其TCP低功率判断、地图或消息功能不能直接记入上述组合。没有启动、清空或迁移现有MySQL。现有MySQL库需部署前备份并执行一次V11，不随本轮测试自动执行；Compose全新空卷已按011顺序挂载V11，现有卷不会自动重跑初始化。

## 自动验证

- 管理端：`npm test`、`npm run build:connected`、`npm run build:pages`。
- 用户端：`npm test`、`npm run build:h5:connected`、`npm run build:mp-weixin`。
- 后端：Java 17下执行`mvn test`，H2隔离测试；JUnit XML报告在`backend/target/surefire-reports`。运行日志及浏览器截图为本地工作文件，个人DOCX不进入公开仓库。
- 前端构建的大包体警告及小程序未配置AppID提示不等同编译失败，也不代表部署和真机通过。

## 浏览器联机验收

使用同一个隔离后端，分别登录管理员、普通用户和运营员，验证列表找站、场景筛选、空站点、收藏、启动、管理端查同一订单、结束结算和释放、用户报修、管理员分派、运营员处理、用户查看进度，以及指标到设备列表的筛选。实测13项断言通过：管理员概览、异常设备关联、清除筛选、用户登录共用目录、空配置站点、收藏、真实页面启动、管理端读取同一订单及电费快照、结束结算与释放、上下文报修、管理员分派、运营员结果回显、无浏览器运行时错误。未伪造接口响应。截图在本地工作文件，测试代码位于本地计划工作区。

## 交付边界

功能验收期间未发布Pages或推送代码；后续源码推送另行记录，不代表正式收款或部署，不修改现有账号、订单或MySQL数据。部署关口为V11增量迁移、实际MySQL回归、整进程重启、地图/扫码及真机验证。无钱包、预约、优惠券或新增AI功能。

最终自动测试数量：管理端74项、用户端69项、后端76项；各套件最终回归结果以执行日志为准。

## 最终复核结果

独立只读复核提出4处问题，均已补充先失败再通过的回归验证：报修分派保存数据库规范账号，避免MySQL不区分大小写时工单无法领取；全新Compose卷补V11挂载；当前异常设备排除历史启动失败而保留事件告警；地图停用设备不误计为离线。异常卡片关联筛选同步使用当前异常口径。最终219项测试通过，管理端联机/Pages和用户端H5/微信构建通过；修正后13项浏览器联机断言再次通过。Compose挂载验证是配置回归，并非已启动真实MySQL新卷。
