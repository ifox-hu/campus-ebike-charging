# 充满自停与双渠道演示实施计划

**目标：**在既有用户端与共享后端补齐可验证的充满自停和微信/支付宝演示支付。

**架构：**扩展既有订单模式、软件计量器、后台调度器与 mock-payment 接口；保留支付宝沙箱。新增字段仅供新订单使用。

**技术：**uni-app Vue 3、Node test、Spring Boot 3.5、MyBatis、H2/JUnit。

**设计：**../specs/2026-11-12-full-charge-demo-design.md

## 重点核验

旧订单不会套用新曲线；延迟任务只计量到截止时刻；模拟渠道不能覆盖沙箱订单；只有后端确认后显示模拟成功；页面隐藏不会让联网调度依赖客户端。
